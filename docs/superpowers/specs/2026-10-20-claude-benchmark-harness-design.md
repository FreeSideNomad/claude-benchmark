# Claude cross-environment coding benchmark — design

Date: 2026-10-20

## Goal

Measure Claude Code's coding performance and cost across four access environments —
personal subscription, personal API key, work subscription, work API key — using a
fixed, self-authored set of deterministic Python coding tasks. The four environments
are already configured via shell functions in `.zshrc`; this project does not manage
credentials or switching, only the benchmark content and the runner/report tooling.

Non-goals: multi-language support (v1 is Python-only), LLM-judged scoring, automated
environment switching, tracking literal subscription quota/rate-limit consumption.

## 1. Task set

12 self-authored tasks, Python only, under `tasks/<task_id>/`:

- **Difficulty**: 4 easy / 4 medium / 4 hard.
- **Categories** (2 tasks each): bug-fix, feature-add, refactor, algorithm,
  multi-file-reasoning, perf-optimization.
- Each task directory:
  - `meta.yaml` — id, title, difficulty, category, short description.
  - `prompt.md` — the exact, fixed prompt text given to Claude Code. Never
    randomized or templated at run time.
  - `seed/` — the starting repo state. This is the *only* code Claude Code sees.
  - `requirements.txt` — pinned deps needed to install and run the task's code/tests.
  - `tests/` — hidden pytest suite. Not present in `seed/`; copied in by the harness
    only after Claude Code's run completes, so the agent cannot read or special-case
    the grading tests.
- Tasks must be self-contained and offline — no network calls, no external services —
  so a result reflects the model/harness, not network flakiness.

Task authoring itself (writing the 12 tasks) is implementation work, done after this
design is approved, not part of this spec.

## 2. Harness architecture

```
claude-benchmark/
  tasks/<task_id>/{meta.yaml, prompt.md, seed/, requirements.txt, tests/}
  harness/
    run.py              # orchestrator
    report.py           # aggregator + HTML dashboard generator
    lib/
      worktree.py        # create/destroy a disposable git worktree per run
      claude_runner.py    # invoke `claude` non-interactively, parse JSON result
      scorer.py           # overlay hidden tests, run pytest, return pass/fail
  results/
    <env>.jsonl          # one file per environment, append-only
  reports/
    dashboard.html        # generated by report.py
```

Python stdlib only for the harness itself. Per-task environments are built with
[`uv`](https://docs.astral.sh/uv/) (`uv venv` + `uv pip install`) instead of plain
`venv`/`pip` — faster to create and tear down per run, which matters at 12 tasks ×
3 repeats × 4 environments = 144 ephemeral installs. No database — results are
append-only JSONL, one file per environment, so work/personal runs done on separate
machines can simply be copied into the same `results/` dir and merged by `report.py`.

## 3. Execution flow

Invocation: `python harness/run.py --env personal-sub` (env label is purely a tag
chosen by the user — the harness assumes whichever shell environment it's invoked
in is already correctly configured; it performs no credential switching). Repeats
per task are fixed at 3, not a CLI option (see rationale below).

For each task × repeat:

1. Create a fresh git worktree, copy the task's `seed/` into it as the initial commit.
2. `uv venv` inside the worktree, then `uv pip install pytest -r requirements.txt`
   (pytest is always installed by the harness itself — task authors only list their
   own code's dependencies).
3. Run:
   ```
   claude -p "$(cat prompt.md)" --output-format json --permission-mode acceptEdits
   ```
   with cwd set to the worktree, so Claude Code can edit/run files freely without
   interactive permission prompts (safe because the worktree is disposable).
4. Parse the JSON result for: `cost_usd`, input/output/cache token counts,
   `duration_ms`, `num_turns`, and `model`. Separately capture `claude --version`.
5. Copy `tests/` into the worktree (overlaying, not visible beforehand) and run
   `pytest -q`; exit code 0 ⇒ pass.
6. Append one JSON row to `results/<env>.jsonl` (schema below).
7. Delete the `uv`-managed venv and remove the git worktree.

A run is always 3 repeats per task per environment (fixed, not configurable down),
to produce a pass-rate spread and a cost/duration spread per task rather than a
single noisy point — Claude Code can't be pinned to deterministic sampling, so
"fairly deterministic" here means deterministic *scoring*, with repeats absorbing
agent-side variance.

## 4. Results schema (one JSON object per line)

```json
{
  "env": "personal-sub",
  "task_id": "medium-03-refactor-cache",
  "repeat": 2,
  "pass": true,
  "cost_usd": 0.0421,
  "input_tokens": 18234,
  "output_tokens": 912,
  "cache_read_tokens": 15000,
  "duration_ms": 48213,
  "num_turns": 6,
  "model": "claude-opus-5",
  "claude_code_version": "2.x.x",
  "timestamp": "2026-10-20T14:03:11Z"
}
```

## 5. Reporting

`python harness/report.py` reads all `results/*.jsonl` files and:

- Prints a markdown/terminal comparison table: per environment × per task, pass-rate
  (x/3), median cost, median duration, median tokens; plus an overall per-environment
  rollup.
- Flags any task/repeat where `model` or `claude_code_version` differs across
  environments — this would confound the comparison (e.g. work org routing to a
  different default model), so it must be surfaced, not silently averaged over.
- Always generates `reports/dashboard.html`, a self-contained static HTML dashboard
  (no external requests) with the same comparison, suitable for opening locally or
  publishing as a Claude Artifact as a separate manual step.

## 6. Repro / determinism controls

- Every result row records `model` and `claude_code_version`; the report highlights
  drift between environments instead of masking it.
- Every task run gets a fresh `uv`-managed venv built only from that task's own
  `requirements.txt` — no leakage from the invoking machine's global Python env.
- Tasks must be offline/self-contained (see §1).
- `prompt.md` is fixed, committed text — never generated or randomized at run time.
